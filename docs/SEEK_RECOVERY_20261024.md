# VQF 定位取消恢复与有界缓存补充

日期：2026-10-24。本记录补充同日 `COMPLETION_20261024.md`，不覆盖旧发行包摘要。

## 已完成

- 失败的 `Seek` 保持时间参数不变；后续 `Read` 恢复调用前的逻辑位置，避免从定位扫描中间继续而丢失 PCM。恢复途中再次取消仍保留原恢复目标。
- 定位时解出的 PCM 写入既有 4 MiB 历史缓存。远距离跳转后回退 500 ms，由此前额外读取 524,288 字节源数据改为零源 I/O；返回的 PCM 完全相同。
- 原 `SetCallback` 两帧预热仍在恢复路径上执行，与未调用回调的直接 Read 路径分别验证。缓存容量、浮点精度和 DLL 依赖不变。

## 压缩数据索引的边界

固定 FFmpeg 9.0.2 的 `libavformat/vqf.c::vqf_read_seek` 可以用码率和帧比特数计算位置，并恢复比特对齐。但 `libavcodec/twinvq.h::TwinVQContext` 同时维护 `lsp_hist`、`bark_hist`、前帧重叠缓冲及块位置。仅跳到一个压缩帧不等于恢复全部历史状态。

没有加入未经证明的“提前若干帧就一定等价”策略，缓存外仍准确重放。真正的远距离检查点需要同时恢复容器比特状态和解码器内部预测/重叠状态；现有公开接口没有通用状态快照，继续保留为后续工作。

## 验证

Windows 11 本机：`song96.vqf` 与 `achterba.vqf` 各自覆盖有/无回调预热，零/1 ms/中间/末尾/超出末尾定位、近期零 I/O 回退、缓存外重放、读或 Seek 取消及恢复期间再次取消。返回 PCM 与同一 DLL 完整解码切片逐字节相同。另重跑预热模式的 8 组 Read 取消矩阵，通过。

RM/VQF 联合测试共 45 次进程运行成功，243 个定位/故障场景；44 个未到达源 I/O 的注入分支单独记录为 SKIP。此数量是两插件联合结果，不是 VQF 独立用例数。最长 VQF 样本约 120 秒；没有据此声称小时级文件或全部历史 TwinVQ 模式均已验证。

Win32 Release 构建及 XP/Win7 静态导入检查通过（4 个系统 DLL、144 个导入）。最终 `2026.10.24p1` DLL 已在 XP SP3、Win7 SP1 和 Windows 11 完成联合 45 项矩阵，各系统失败为 0。原版与重建版的 VQF 实际播放在三系统通过。

私有测试和日志位于工作区 `rebuild/tests/plugins_followup_20261024/seek`，不进入 Action、仓库或发行包。
