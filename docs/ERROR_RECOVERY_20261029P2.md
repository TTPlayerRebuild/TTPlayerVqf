# VQF 预热取消与损坏帧错误恢复

构建版本：`2026.10.29p2`。接续 [定位取消恢复](SEEK_RECOVERY_20261024.md)，本轮修正此前未覆盖的两条状态路径。固定 FFmpeg 9.0.2、TwinVQ 算法、旧 Reader ABI 和正常 PCM 均保持不变。

## 两帧预热中断后丢失播放起点

原 `801D1AD7` 的 `SetCallback` 会解码并丢弃两帧，详见 [原接口分析](IMPLEMENTATION_AND_VALIDATION.md)。当前重建后端也先暴露这两帧，由包装器在相同入口丢弃；不能直接去掉包装器预热或再让后端跳两帧。

旧重建实现只在全部预热完成后设置 `primed_`。如果 IStream 在此期间返回取消，已经读取的压缩数据可能被消耗，但该标记仍为 false。随后 `Start`／`Read` 从头恢复解码时把它当成原始、无需预热的入口，向宿主多返回两帧。

独立短读探针在真实 `song96.vqf` 上复现：正常回调后输出 20,398,080 字节；预热取消后恢复输出 20,430,848 字节，多出 **32,768 字节**。使用旧 `2026.10.24p1` DLL 的负对照失败，新版同样输入逐字节恢复正确输出。

本次增加独立的“预热已请求”状态：

- 请求预热时先记录意图，成功后再标记完成。
- 取消恢复重开解码器后，已完成和正在进行的预热都恢复相同的两帧播放起点。
- `SetCallback` 重试、直接 `Start`／`Read`、显式 `Seek` 和恢复途中再次取消共用该恢复状态。
- 不足两帧的合法短文件按现有 EOF 规则结束；重放不错误地要求一定取到两个帧。
- 正常原始 Read 入口仍暴露前两帧，未改成无条件预热。

该恢复针对可定位输入，沿用既有的重放条件；本轮没有声称不可定位网络流可以任意回退。

## 损坏窗口帧的错误被后续读取吞掉

TwinVQ 的窗口类型只有 0～8 合法。测试只在合法文件第 4、21、400 个压缩帧把这四个比特改为非法值 15，不修改其他压缩帧或容器头。

旧版首次读取报告 `ERROR_INVALID_DATA`，下一次却继续返回后面的 PCM。例如 `song96` 的第 21 帧损坏后，先返回错误，再返回成功的 16,384 字节。预测／重叠历史已经不完整，不能把重试 Read 当成未受影响的正常播放。

本次借鉴 RM 已验证的错误管理方式，锁存不可恢复的解码损坏：

- 连续 Read、Start 和缓存回放到损坏位置时保持原错误，不悄悄变成成功 PCM 或正常 EOF。
- 定位到较早的有效位置仍可读取有效前缀；需要重开时重建解码历史，再到相同损坏位置报错。
- IStream 取消和可恢复 I/O 错误仍走现有恢复流程，分配失败不被固化为格式损坏。
- 最后不完整压缩帧的既有 VQF EOF 兼容规则未变；该情况与解码器识别出的非法窗口类型分开处理。
- 解码器初始化失败时释放未打开的 context，后续调用不把残留指针误认作已准备完成。

这是恢复重建版的可预测错误行为，不宣称原版所有网络丢包／错误隐藏算法已经复刻。

## 验证

所有测试仅保存于私有 `rebuild/tests/plugins_followup_20261029p2/rm-vqf`，未加入 Actions 或发行源码包。

本机最终平铺入口共 **28 组**：

| 组别 | 数量 | 验收条件 |
| --- | ---: | --- |
| 两个完整文件及各自两帧短文件的预热取消 | 4 | 每组 16 个子场景，共 64 个；恢复后完整 PCM 与正常回调基线逐字节相同 |
| 正常文件修复前／后对照 | 2 | 原始读取、回调预热后的完整 PCM 均逐字节不变 |
| 两个文件各三个损坏帧位置 | 6 | 重复 Read、Start、缓存回放／缓存外重开后的终止错误与有效前缀一致 |
| 既有定位／取消／重复恢复 | 16 | 两文件、有／无回调，四种场景；定位后 PCM 与本版完整输出逐字节一致 |

预热故障在实际源读取的第一次和最后一次注入，并分别在失败前消耗 0／13 字节；恢复方式为 Read、回调重试、Seek 或再次取消。短读长度为 64 字节。既有定位测试中未触发底层 I/O 的注入仍明确记为 SKIP，不计算为注入成功。

Windows 11、XP SP3、Win7 SP1 使用同一最终 DLL，均为 `VQF_BOUNDARY_CASES=28 FAILURES=0`；两个旧 DLL 负对照均按预期失败，单独保存在 `boundary-results.json`，不计入 28 个成功回归组。虚拟机日志为同一私有目录的 `xp-result.log` 和 `win7-result.log`；实际宿主验证由主任务另行记录。

同轮检查了当前 RM `2026.10.29p1` 的对应错误路径：6.5／8.5 kbps 截断 SIPR 在重复 Read、Start、缓存从头回放后仍保持 `ERROR_INVALID_DATA`，有效前缀相同。本轮没有修改 RM，也没有重复发布相同 RM DLL。

## 产物与边界

- DLL：`2026.10.29p2`，804,352 字节。
- SHA-256：`25f0de9d414af956a4e7c543e4455ca3bd8382583ca866b4f906c0e99601f24e`。
- Win32、子系统 5.01，VC-LTL／YY-Thunks；静态导入检查通过，4 个系统 DLL、144 个导入。
- 没有新增 VC2012、原 `tvqdec.dll` 或其他外部运行依赖。
- 本轮未扩大 TwinVQ 模式支持，也没有实现丢包隐藏、任意压缩位置的无历史跳转或小时级流状态快照。

平铺 `vmstage` 约 5.75 MB，只包含探针、音频、私有旧版对照 DLL、新 DLL 和 `run.cmd`，不保存多份完整 PCM。实际发行包仍只需新 DLL 与 SHA256SUMS；源码按既有独立附件方式提供。
