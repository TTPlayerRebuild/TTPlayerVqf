# TwinVQ/VQF 重建：依据、差异和验证

## 1. 原版本

原 `AddIn/ttp_vqf.dll`：28,160 字节，SHA-256 `0c5f655766521a671129566fc768c901d65f905a418a7e567c9b7484394b0de8`。
原 `AddIn/tvqdec.dll`：573,440 字节，SHA-256 `45aaced6f552f73be099c91ecf17ba4611050607961896217864cada9efe8fef`。
同一二进制 Ghidra 导出为依据，原文件未修改。

| 地址 | 原实现 | 新版 |
|---|---|---|
| `801D1000 / 801D6158` | 单工厂与 Reader 虚表 | 原导出、GUID、接口顺序 |
| `801D17CA` | TwinVQ 头与外部 DLL 初始化 | IStream 自定义 AVIO＋FFmpeg TwinVQ |
| `801D1AD7` | SetCallback 一次解码并丢弃两帧 | 同样在回调设置时预热 |
| `801D1B4B` | float32 输出及 ±32700/32768 限幅 | 同格式和限幅 |
| `801D1C55` | 定位 | 新版按样本解码丢弃 |
| `801D613C / 801D16BC` | Metadata，Set 返回 E_NOTIMPL | 文字标签只读 |

## 2. 已恢复行为

原有 Title／Artist／Copyright／Comment 读取、键名顺序、ANSI 兼容、VQF Reader 工厂名、扩展名串、float32、单声道／立体声、数据容量与推荐帧长度。原 DLL 没有 Thumbnail，Metadata.Set 的机器码明确返回 E_NOTIMPL，因此不宣称原版已有标签写入或封面保存。

FFmpeg 默认跳过开头两帧，而原包装器在 SetCallback 时才跳过。兼容补丁让 TwinVQ 核心返回开头两帧，再由包装器按原回调时机丢弃。直接 Read 与实际播放回调两种入口都已比较，避免双重跳过或补假静音。

该分支同时将初始 `curr_frame`／`prev_frame` 重叠缓存清零。上游使用未清零分配，但正常丢弃两帧，不向宿主暴露初始历史；直接返回首帧后若不初始化，会把旧堆内容混入 PCM。Win7 双 Reader 回归发现此问题，本机以 16 字节对齐的 `0x3f` 堆污染稳定复现：修复前仅第一帧 4,096 字节内出现差异，修复后两个 Reader 完整输出相同。

新版每个 Reader 有独立解码状态，可并行打开文件。原能力位 8 用于禁止重叠播放，因为旧 tvqdec 是进程全局解码器；新版不再设置该位。只读标签能力保持不变。

容量不足返回 E_INVALIDARG，不越过调用方缓冲区；EOF 清零输出长度。短读、原扩展 ReadWait、回调、取消、错误 HRESULT、非零 IStream 初始位置、按需解码器初始化均有保护。末尾不完整 VQF 压缩包按原包装器规则视作 EOF，但不吞真正 IStream 或解码器错误。

## 3. 真实对照结果

| 样本 | 原／新直接 Read 字节 | 原／新 SetCallback 后字节 | float 最大绝对差 | RMS 差 |
|---|---:|---:|---:|---:|
| achterba，22050 Hz mono | 10,600,448 | 10,592,256 | 0.000322178 | 0.0000297202 |
| song96，44100 Hz stereo | 20,430,848 | 20,398,080 | 0.000120401 | 0.00000840818 |

长度完全对应；现代浮点核心与旧 TwinVQ 核心并非位精确。表中差值覆盖完整回调后输出，不只挑选少量片段。

无回调直接 Read 的两帧预热输出不能宣称音频位精确：mono 全曲最大差仍为 0.000322178，stereo 的差异集中在原播放器正常会丢弃的前两帧，最大达 0.845230475；回调后的输出仍为表中精度。初始化修补不改变此前正常堆环境下的输出，仅消除未初始化内存依赖。

原 mono 样本时长报告 150,104ms，而实际约120秒，新版按负载码率得到120,083ms；这是修正原公式对该码率组合的偏差。stereo 原57,904ms，新版57,907ms，来自取整边界。推荐缓冲区由解码器的单帧长度给出；header-only 还未初始化时使用足够的保守上限。

两个样本均已通过容量／采样对齐、Stop/Start、500ms 定位结果与整曲切片相同、双 Reader、31 字节短读、flags=0 首次 Read、137 字节前缀 IStream。旧 tvqdec 保留在本地对照目录，没有带入新发行包。

## 4. 边界与限制

- 向后定位会重新解码并丢弃到目标样本，保持稳定结果，但没有恢复原常码率按帧跳转的速度。
- 当前覆盖两个常用模式；其他码率／采样率组合、极端损坏码流、GUI 全部控制与错误流程及慢网络并发取消仍需更多实测。
- 未加入标签写入／封面扩展，保持原 Metadata.Set=E_NOTIMPL 的事实。
- Windows 10 没有独立实机；按用户要求由 Windows 11 承担新系统验证，记录保留实际测试系统。
